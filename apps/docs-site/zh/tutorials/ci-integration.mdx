有人改了 prompt，本地试了两次觉得没问题就合并了，第二天才发现另一类问题全答错了。把评估放进 CI，每个 PR 都自动跑一遍，回归在合并前就能被发现。

CI 里跑的就是你本地用的那条 `niceeval exp`，不需要额外配置：

- 评估不通过、运行出错或被中断时，进程以非零状态退出，CI 自然变红。
- 加 `--json` 时，最后一行是这次运行的 receipt，里面有新建的 Run ID，后续步骤可以用它读取结果。
- 加 `--junit <path>` 时，会写出 JUnit 文件，让 CI 平台按测试用例展示结果。

## 基本命令

只要存在 mismatched 的 required Boolean condition、低于 `.gate(minimum)` 最低值的 measurement，或执行错误，[NiceEval](https://niceeval.com/) 就以非零状态码退出。通过制和计分制都读取显式 gate；没有全局 strict，也不会在读取时把 stop-only condition 提升成 gate。需要阻止合并的要求直接写在评估用例源码中，CI 与本地运行读取同一套判定。

```sh
npx niceeval exp ci --json --junit ./artifacts/niceeval-junit.xml
```

这条命令有三种输出：

- 退出状态：CI 用它决定任务成功或失败。
- NDJSON：progress 与 diagnostic 描述当前进程；最后一条 receipt 描述 Invocation。
- JUnit：供 CI 平台读取的临时文件。

JUnit 和外部平台文件不拥有 Record。Verdict、Usage、断言和诊断的持久事实仍在停稳 Record 的具名通道中。

## GitHub Actions 示例

下面的步骤保留 JSON 输出，并正确传回 `niceeval exp` 的退出状态：

```yaml
- name: 运行评估
  shell: bash
  run: |
    set -o pipefail
    npx niceeval exp ci --json --junit ./artifacts/niceeval-junit.xml \
      | tee ./artifacts/niceeval.ndjson
    exit "${PIPESTATUS[0]}"

- name: 上传 JUnit
  if: always()
  uses: actions/upload-artifact@v4
  with:
    name: niceeval-junit
    path: ./artifacts/niceeval-junit.xml
```

将模型凭据作为 CI secret 注入命令运行所需的变量。不要把凭据写入 Experiment、receipt、JUnit 或日志。

## 用 receipt 关联后续步骤

成功建立 Invocation 后，NDJSON 的最后一行包含 receipt。后续脚本可以读取它的 `runIds`，用明确 Run 审阅或构造 query request：

```sh
pnpm exec niceeval query discover
pnpm exec niceeval view --run 01J9ZK3M6P4T7V9X2C5N8QW0RY --no-open
```

如果命令在建立 Invocation 前就因输入错误退出，不会有 receipt。此时直接修复命令、Experiment 或选择条件；不要猜测 Run ID。

## 让反馈保持可读

CI 日志适合阅读当前进程的 progress 和 diagnostic。需要检查业务结果时，AI、脚本或 CI 先运行 `query discover`，人用 receipt 的 `runIds` 运行 `view`。

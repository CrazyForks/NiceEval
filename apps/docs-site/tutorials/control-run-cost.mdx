A full eval run calls the model hundreds of times, plus Sandbox costs, so the bill easily exceeds expectations. Before controlling cost, decide what you want to save: the number of repeated runs, a ceiling for when things go wrong, or the resources used at the same time.

Each setting controls one thing, and they cannot replace each other.

| Goal | How |
| --- | --- |
| Measure the full stability distribution | Set `attempts: N`; all of them run by default. |
| Only confirm it can succeed at least once | Use `--early-exit`. |
| Protect each Experiment's spending | Use `--budget <USD>`. |
| Limit resources used at the same time | Use `--max-concurrency <count>`. |
| Skip results that were not affected | Use default reuse or `--rerun`. |
| Spread Sandbox creation and preparation costs | Use `sandboxReuse`. |

## See how much will run before running

Before spending money, confirm how many evals and Experiments this run selects, and how many times each eval runs:

```sh
pnpm exec niceeval exp regression --dry
```

`--dry` calls no model and creates no Sandbox. The first line gives the total number of Attempts in this plan, and each following line is one eval, marking which will reuse last results and which will run again.

`--dry` does not predict the final cost. Its job is to catch a wrong scope or too many repetitions before dispatch. When the total is much larger than expected, check the Experiment's `evals` selection and `attempts` first.

## Stop at the first pass when you only care whether it can succeed

When you only want to know "can this task be done" and do not care about the pass rate distribution, turn on early exit:

```sh
pnpm exec niceeval exp regression --early-exit
```

After one Attempt of an eval gets `passed`, that eval's Attempts that have not started are no longer dispatched and are recorded as `not-dispatched`. Attempts of the same eval that are already running receive a cancellation signal through `ctx.signal`; how quickly they end depends on whether the Adapter responds to that signal promptly.

Attempts of the same eval that return after early exit triggers do not enter the results.

`failed`, `errored`, or `skipped` do not trigger early exit. Do not turn this on when you need the full pass rate distribution. Under default concurrency, several Attempts of the same eval may already be running at once, so nothing is saved; to make it really save money, see [Make early exit actually save money](/tutorials/concurrency#make-early-exit-actually-save-money).

## Set a protective spending ceiling

When you worry that a run might get out of hand and spend more than expected, set a dollar ceiling:

```sh
pnpm exec niceeval exp regression --budget 25
```

The budget is calculated separately for each Experiment ID. As each Attempt completes, NiceEval estimates its cost (`estimatedCostUSD`) from the Experiment's `model`, the reported token usage, and the price table, then adds it to the budget. The actual amount `usage.costUSD` reported by a Provider or Adapter is only for display and does not take part in the budget decision.

When the cumulative estimate reaches the ceiling, NiceEval stops dispatching new Attempts; those already running are not stopped midway. So `--budget` is a protective ceiling, not an exact bill: while several concurrent tasks have not settled, the final cost can briefly exceed the setting.

When the budget runs out, you see:

- a `budget_exhausted` diagnostic;
- Attempts that were not dispatched in time recorded as `not-dispatched`;
- the command exiting with a non-zero status.

After raising the budget, rerun the same scope. Attempts that already completed and qualify for reuse are reused directly, and only the remainder runs.

When `model`, token usage, or a matching price is missing, NiceEval cannot compute an estimated cost, and `usage.costUSD` cannot fill the gap. The run then gives a warning instead of pretending the budget is still in effect. When you see this warning, first confirm the Experiment sets `model` and the Adapter reports token usage.

## Concurrency only controls resource use

When the local machine or the Provider cannot keep up, limit the number of Attempts running at once:

```sh
pnpm exec niceeval exp regression --max-concurrency 4
```

A concurrency limit is not a cost limit; cost protection still uses `--budget`. Sandbox build concurrency is controlled by a separate flag, `--max-build-concurrency`.

To also spread out the creation and preparation time of each Sandbox, see [Reuse Sandboxes](/tutorials/sandbox-reuse). To choose between rerunning only failures and revalidating everything, see [Rerun and Reuse Results](/tutorials/rerun-and-cache).

## See how much was spent

After the run, view the cost of one Attempt or a whole experiment in the terminal:

```sh
pnpm exec niceeval show @attempt-locator
pnpm exec niceeval show --experiment regression
```

To browse in the browser, run `pnpm exec niceeval view`.

The Attempt page first shows the combined cost of the application and the Judge:

- When the cost is complete, it shows the total.
- When receipts, prices, or complete call records are missing, it shows the known subtotal and which parts are missing.
- An explicitly recorded zero amount counts as a known cost. Money already spent on failures and retries is kept too.

Model purpose, each actual call, and Judge costs are in the breakdown below.

The experiment page sums the latest result of each Attempt of each eval, counting the same original Attempt only once. Old results replaced by a rerun are not added, and results that were not rerun are kept. So it shows the cost of the current batch of results, not a bill for all historical runs. Omitting a few rows in the breakdown does not reduce the total; different currencies are shown separately without exchange-rate conversion.

## Have a custom Adapter report cost

For costs from your own application Adapter to appear on the pages above, report the usage of each call:

- Use `ctx.recordUsage(call)` to report the final snapshot of each physical call.
- After all records are obtained, call `ctx.sealUsage({ state: "complete" })` to tell NiceEval this record is complete.
- When only part of the records could be read, call `ctx.sealUsage({ state: "partial", reason: "source-incomplete" })`.

An empty record that was not declared complete shows as an unknown cost, never as zero.

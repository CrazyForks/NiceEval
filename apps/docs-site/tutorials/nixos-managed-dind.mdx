Use Incus VMs for eval tasks that need Docker on NixOS. Eval configuration is the same as on other Linux hosts; see [Run Docker Inside a Sandbox](/tutorials/docker-in-docker).

## What the administrator provisions

An administrator must provision Incus, the runtime project, storage pool, trusted base image, and `/etc/niceeval/incus-provider.json`, and grant the everyday user the required access. Reference environments need dedicated storage and verifiable capacity. Development environments require separate configuration.

The NiceEval repository's `nixosModules.default` and `nixosModules.docker-profiles` configure Docker Profiles. They do not provision the Incus environment required here. Successfully starting `services.niceeval.dockerProfiles` services does not establish that Incus is ready.

This page does not provide a one-command Incus deployment module. Host changes belong in system configuration; installing the eval project's npm dependencies does not install or update these services.

## Check the environment as the everyday user

In an eval project with NiceEval installed, run:

```bash
pnpm exec niceeval sandbox provider doctor incus
```

For a development environment, run:

```bash
pnpm exec niceeval sandbox provider doctor incus --development
```

`doctor` checks configuration, trusted images, objects, and capacity without changing them. Ask the administrator to fix permission errors instead of bypassing everyday-user checks with `sudo pnpm exec niceeval ...`.

## Connect the Experiment

Obtain the full image digest, project, and storage pool from the administrator and pass them to `incusSandbox()` using the [Incus configuration steps](/tutorials/docker-in-docker#select-incus-in-the-experiment). Development environments require `acceptDevelopmentDomain: true`.

Run the experiment with `--dry` to check capabilities and environment selection, then run the actual eval. Passing host checks and completing an actual eval are separate validations.
